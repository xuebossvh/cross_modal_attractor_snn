# P4：固定样本拟合与等预算续训诊断

P4 使用 seed1234 的原第 100 轮完整 `last.pt`，保留原模型、检测器冻结范围、音频 refiner 旁路、损失与训练数据协议。新代码位于 [tools](../tools/)，所有结果写入独立目录。入口是 [run_v15_p4_suite.py](../tools/run_v15_p4_suite.py)。

套件依次执行以下四步：

1. **固定小样本拟合**：原训练集每类 6 对、共 60 对；另取独立验证集每类 6 对。缓存两种噪声、uniform/foreground 两种位置策略及原双模态 cue 条件。重建 Adam，基础学习率 `5e-5`，沿用原参数组倍率；固定 batch60，执行 **1000 次参数更新**，每 100 次评估固定 train60/val60。模式比例每 100 次为 clean 10、双污染 40、两个单侧污染各 25；不要求总损失归零。
2. **keep_lr**：从原第 100 轮完整 `last.pt` 单独续训 30 轮，保留原 Adam 动量和步数，使用末期学习率路径。
3. **restart_lr**：从**同一份原始** `last.pt` 单独续训 30 轮，保留同样的 Adam 状态，采用预定温和学习率重启。两分支使用相同的原训练协议、逐轮种子、数据顺序及完整验证规则。A/B 都不从 tiny 权重开始。
4. **结果核验与阶段报告**：核验两个分支的来源、预算、训练流及完整验证结果，分别报告验证选出的 best 与第 30 轮 last，并生成固定 train60/val60 的阶段诊断。[report_v15_p4.py](../tools/report_v15_p4.py) 生成报告。

小样本的 1000 次更新是独立诊断；A/B 合计 **60 个正式作业轮数（每支 30 轮）**。固定 60 对的指标不能替代完整验证集，也不用于挑选 checkpoint。本实验不读取测试集来选模。

## 环境、路径与执行

在目标机器激活原环境，并进入本项目根目录：

```bash
source /root/autodl-tmp/snn-env/bin/activate
cd /root/autodl-tmp/projects/cross_modal_snn_v15pro_p4
```

目标机器已确认的原始数据根目录是 `/root/autodl-tmp/projects/cross_modal_attractor_snn_v11b/_data`，音频位于其 `fsdd/recordings`。FSDD 参数可指向 `recordings` 本身，指向其父目录时现有加载器会补上 `recordings`。

```bash
python tools/run_v15_p4_suite.py \
  --assets /root/autodl-tmp/projects/cross_modal_snn_v15pro_p4/assets/v15pro_p4_assets \
  --output /root/autodl-tmp/projects/cross_modal_snn_v15pro_p4/outputs/p4_seed1234 \
  --data-root /root/autodl-tmp/projects/cross_modal_attractor_snn_v11b/_data \
  --fsdd-root /root/autodl-tmp/projects/cross_modal_attractor_snn_v11b/_data/fsdd/recordings \
  --device cuda --threads 2 --cuda-memory-fraction .95 \
  --wait-for-gpu-idle-before-continuation
```

默认只校验资产及原运行时代码并保存 `plan.json`，**不会启动训练**。检查计划后，在相同参数末尾加 `--run` 执行：

```bash
python -u tools/run_v15_p4_suite.py \
  --assets /root/autodl-tmp/projects/cross_modal_snn_v15pro_p4/assets/v15pro_p4_assets \
  --output /root/autodl-tmp/projects/cross_modal_snn_v15pro_p4/outputs/p4_seed1234 \
  --data-root /root/autodl-tmp/projects/cross_modal_attractor_snn_v11b/_data \
  --fsdd-root /root/autodl-tmp/projects/cross_modal_attractor_snn_v11b/_data/fsdd/recordings \
  --device cuda --threads 2 --cuda-memory-fraction .95 \
  --wait-for-gpu-idle-before-continuation --run
```

执行前会核验资产文件 SHA256、原始 runtime 指纹、MNIST 原始训练张量、训练 WAV 和原归一化统计。只允许映射路径，不重新估计归一化。资产应来自 [package_v15_p4_assets.py](../tools/package_v15_p4_assets.py)，包含完整 last、原验证 best 参考、train60/val60 与原归一化文件。

`--threads 2` 同时传给分支/报告，并通过 OMP/MKL/OpenBLAS 环境变量限制各子进程线程。CLI 默认 CUDA 分配上限仍为显存的 60%；这台机器的完整 batch128 前向检查已触及该上限，因此上述正式命令显式使用 **95%**。上限不等于预先占满显存；tiny 的实际用量较小，可先运行。

`--wait-for-gpu-idle-before-continuation` 让 tiny 立即执行，在 keep_lr 和 restart_lr 启动前分别等待其他 GPU 计算进程退出。套件每 10 秒重新查询当前 PID，忽略自身 PID；列表变化或每 60 秒写入控制台及 `logs/gpu_wait.log`。等待期间 `suite_manifest.json` 的状态为 `waiting_for_gpu`，包含当前阶段和外部 PID。PID 退出后会重新检查锁与来源，然后继续。该等待属于当前手动启动的套件，不创建后台定时任务。查询失败或 CUDA 不可用会明确报错；实际训练内存不足时也停止，不减小 batch 或切换 CPU。等待开关与显存比例都写入严格恢复身份。

## 恢复与输出

已启动的套件必须带 `--run --resume`，其他参数、源资产、脚本内容和输出路径必须一致。suite 会让 tiny、两个续训分支及报告分别执行各自的恢复校验，即使该阶段已经完成。仅有阶段 manifest、尚无可恢复 checkpoint 的初始化残留会明确报错，需要使用新的套件输出目录。

PID 锁阻止同一目录同时启动两个套件。旧锁仅在原启动器及其子进程均已退出后可回收；中断启动器但子进程仍在运行时不会被当作空闲目录。

输出目录包含：

| 路径 | 内容 |
|---|---|
| `suite_manifest.json`、`plan.json` | 套件来源、参数、顺序、状态与计划 |
| `logs/tiny.log`、`logs/keep_lr.log`、`logs/restart_lr.log`、`logs/report.log` | 分阶段子进程日志，放在分支目录之外 |
| `tiny/` | 每次更新的 loss/梯度、每 100 次的评估、终点 checkpoint、起点/终点全部固定样例 NPZ |
| `keep_lr/`、`restart_lr/` | 各自的 manifest、30 轮记录、原验证规则选出的 best、末轮 last |
| `report/summary.json`、`report/report.html` | 可追溯数值、完整验证对照及阶段诊断 |

图像阶段为 coarse 概率 → 实际 refiner delta 加到 coarse 并裁剪后、回填前 → final。音频 refiner 始终旁路，因此仅报告 coarse → final，后者变化应解释为回填。报告覆盖真实命中修复区、漏检、干净误报、有效前景、结构梯度误差与饱和比例。原总 loss 的 binding 和 teacher 流程保持，真实污染 mask 只供损失与评价，不传入 predicted forward。

套件完成状态为 `complete_awaiting_scientific_review`：所有执行及报告产物已完成，科学解释仍需复核；不会自动更新共享实验计划。**P5 图像细节与 P6 音频细节是两个独立且均保留的后续任务**，P4 分别为它们提供证据，不作二选一，也不把任何 P4 功能测试记作 P5/P6 正式结果。
